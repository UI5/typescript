Interface: ActionHelpers

import ActionHelpers from "sap/ui/joule/frontend/util/ActionHelpers";

Experimental

Helper utilities for implementing frontend actions with Joule. These functions provide reusable implementations of common frontend action patterns, allowing applications to easily expose UI introspection and manipulation capabilities to Joule without implementing the underlying logic themselves.

The describeUI and describeUIElement methods automatically enrich UI elements with jouleControlEnrichment metadata from control designtime files when available. This allows controls/libraries to provide Joule-specific metadata (e.g., column names for SmartTable).

As of version 1.151.

describeUI()

describeUI(oRootControlOrParams?, oParams?): Promise<any[]>

Experimental

Describes the UI by returning a hierarchical tree representation of visible UI elements.

This function provides a structured view of the UI with simplified control types and hierarchical nesting (containers have their children nested, select controls have their options as children, etc.). This is useful for Joule to understand the UI structure and relationships between elements.

Automatically enriches elements with jouleControlEnrichment from designtime metadata when available. Smart controls (SmartTable, SmartChart, SmartFilterBar) and their inner controls are properly captured in the hierarchy.

Response structure:


[
  {
    id: String,             // Unique control ID
    label: String,          // Human-readable label
    type: String,           // Simplified type (e.g., "smartTable", "input", "button", "form")
    description: String,    // Optional description/tooltip
    value: any,             // Current value of the control
    editable: boolean,      // Whether the control is editable
    valueTypeHint: String,  // Type hint (String, Integer, Float, Boolean, Date, Object)
    jouleControlEnrichment: Object,   // Optional jouleControlEnrichment from designtime metadata
    children: Array         // Nested child elements
  }
]

Container types (form, panel, page, smartTable) will have their child controls nested in children. Group controls (selectGroup) will have selectOption children. Select controls will have selectOption children for their items.

Parameters

oRootControlOrParams?

object | Control

Root control to start scanning from, or params object if no root control

oParams?

Optional parameters (only when first param is root control)

excludedElementTypes?

string[]

Simplified type names of controls to exclude from the response (e.g., "Table", "SmartTable", "Toolbar"). Case-insensitive. When omitted, nothing is excluded.

includedProperties?

string[]

Properties to include in response elements. Uses SAP GUI naming convention (mapped internally). When omitted, all properties are included.

rootElementId?

string

Start ID of the tree. When provided, the control with this ID is used as root (only its descendants are returned).

Returns

Promise<any[]>

Promise resolving to hierarchical array of UI elements

describeUIElement()

describeUIElement(oRootControlOrParams?, oParams?): Promise<object>

Experimental

Describes a specific UI element by its control ID.

This function locates a control by its ID and returns a detailed description of that specific control with its children (if any). The description includes simplified types, labels, values, and hierarchical children.

Automatically enriches elements with jouleControlEnrichment from designtime metadata when available.

Response structure (on success):


{
  id: String,             // Unique control ID
  label: String,          // Human-readable label
  type: String,           // Simplified type (e.g., "smartTable", "input", "button")
  description: String,    // Optional description/tooltip
  value: any,             // Current value of the control
  editable: boolean,      // Whether the control is editable
  valueTypeHint: String,  // Type hint (String, Integer, Float, Boolean, Date, Object)
  jouleControlEnrichment: Object,   // Optional jouleControlEnrichment from designtime metadata
  children: Array         // Nested child elements
}

Response structure (on error):

  success: false,
  error: String           // Error message

executeAction()

executeAction(oRootControlOrParams?, oParams?): object

Experimental

Executes a named action on a control (e.g., press a button, select an item).

This function locates a control by its ID and triggers the action specified by actionName. Supported action names: - "press" - firePress() for buttons, links, menu items, tiles - "select" - fireSelect() for selectable controls - "tap" - fireTap() for legacy controls - "toggle" - toggles selected state for checkboxes/switches - "expand" - expands a collapsible control - "collapse" - collapses an expandable control

getFields()

getFields(oRootControlOrParams?, oParams?): any[]

Experimental

Gets all visible UI elements from the application in a flat array.

This function traverses the UI control tree starting from the specified root control and returns an array of all visible UI elements with their metadata (ID, type, value, etc.). Applications can use this in their frontend actions to expose their UI structure to Joule.

Note: This method returns a flat list and does not include jouleControlEnrichment enrichment. Use describeUI() for hierarchical structure with jouleControlEnrichment support.

Response structure:


[
  {
    fieldName: String,      // Unique control ID
    type: String,           // Full control type (e.g., "sap.m.Input")
    description: String,    // Human-readable description (from label, placeholder, or tooltip)
    fieldValue: any,        // Current value of the control
    valueType: String,      // Type of the value (String, Integer, Float, Boolean, Date, Object)
    children: Array         // Child elements (currently empty, reserved for future use)
  }
]

This function locates a control by its ID or label and sets its value. For model-bound controls (like SmartField), it updates the underlying model binding directly. It also fires change events to notify listeners of the value change.

setFields()

setFields(oRootControlOrParams?, oParams?): object

Experimental

Sets multiple field values in a single call.

This function provides a batch operation for setting multiple field values at once. It iterates through each field in the provided array and attempts to set its value using the setField method. Results are aggregated and returned with detailed information about each field's success or failure.

The fields array uses variable-key dict format where each object has a single key (the field ID) mapped to its value: [{"fieldId": "fieldValue"}, ...]

Parameters

oRootControlOrParams?

object | Control

Root control for searching, or params object if no root control

oParams?

Parameters (only when first param is root control)

fields

object[]

Array of single-key objects where key is field ID and value is the field value

Returns

object

Result object with success/error and detailed results
