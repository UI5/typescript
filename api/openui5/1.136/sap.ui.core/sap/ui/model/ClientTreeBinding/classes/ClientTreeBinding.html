Class: ClientTreeBinding

import ClientTreeBinding from "sap/ui/model/ClientTreeBinding";

Tree binding implementation for client models.

Note that a hierarchy's "state" (i.e. the information about expanded, collapsed, selected, and deselected nodes) may become inconsistent when the structure of the model data is changed at runtime. This is because each node is identified internally by its index position relative to its parent, plus its parent's ID. Therefore, inserting or removing a node in the model data will likely lead to a shift in the index positions of other nodes, causing them to lose their state and/or to gain the state of another node. Note: Tree bindings of client models do neither support sap.ui.model.Binding#suspend suspend nor sap.ui.model.Binding#resume resume.

Methods

filter()

filter(aFilters?, sFilterType?): this

Filters the tree according to the filter definitions.

The filtering is applied recursively through the tree. The parent nodes of filtered child nodes will also be displayed if they don't match the filter conditions. All filters belonging to a group (=have the same path) are ORed and after that the results of all groups are ANDed. See: sap.ui.model.TreeBinding.prototype.filter

Parameters

aFilters?

Filter | Filter[]

The filters to use; in case of type sap.ui.model.FilterType.Application this replaces the filters given in sap.ui.model.ClientModel#bindTree; a falsy value is treated as an empty array and thus removes all filters of the specified type

sFilterType?

"Application" | FilterType | "Control"

The type of the filter to replace; if no type is given, all filters previously configured with type sap.ui.model.FilterType.Application are cleared, and the given filters are used as filters of type sap.ui.model.FilterType.Control
